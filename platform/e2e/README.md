# Local E2E Smoke

本目录提供 manifest 驱动的本地 full-stack/E2E smoke。E2E 注册状态以 `harness/project-manifest.json` 为准。

当前 `smoke-test.sh` 覆盖 P2-C / VS-MA-11 的 deterministic processing local smoke：使用临时 workspace 和脚本内生成的 WAV fixture，通过公开 `processing-cli` JSON/exit code 边界串联 `import_media -> generate_transcript` 内部 normalized audio/source selection -> `generate_speaker_labels -> export_transcript -> delete_session`。

该 smoke 覆盖每步 JSON response、exit code、关键 artifact、`session.json` 变化、原始媒体 checksum、用户显式 export target、confirm=false 失败、workspace 外 export 保留和 workspace 级 `meeting_session.deleted.v1` 删除事件。命令 schema 负向、损坏 `session.json`、session lock、导出 metadata 写失败清理、speaker labels 复用再校验、artifact symlink/hardlink fail-closed 等回归由 `platform/processing-cli/scripts/test.sh` 下的组件测试覆盖。它不调用真实 speaker runtime、不上传/下载外部内容，也不依赖真实会议数据或宿主机常驻服务。

`smoke-test.sh` 的 `VS-MA-20 provider/e2e marker [non-contract]` 输出只用于把 provider smoke 证据归因到 import processing chain 的阶段：no-auto-download dependency preflight、invalid delete exit-code path、import checksum、normalized/transcript artifact、speaker transcript-only fallback/no-auto-upload boundary、export conflict/retention 和 delete retention/event。该 marker 文案不是公开 CLI 命令、字段、artifact、error code 或 exit code 契约。

`capture-processing-smoke.sh` 覆盖 VS-MA-20 provider/e2e 的 native_recording-style artifact chain：通过 test-only `source_type=native_recording`、`status=recorded` workspace fixture，验证默认 `mixed_audio`、`system_audio`/`microphone_audio` fallback、lock/path/temp/checksum rollback、no-auto-download/no-auto-upload 边界、workspace 外 export 保留和 delete event summary。它只证明 processing/e2e 可消费 native_recording 形态的 provider artifact，不证明真实 native capture、native UI 触发、release bundle 或真实 runtime 质量。

同一脚本还输出 `VS-MA-21 provider/e2e marker [non-contract]`，用于标记 test-only capture-style provider failure fixture：公开 `generate_transcript --runtime whisper_cpp` 在缺失 runtime/model env 时返回既有 `dependency_missing` / exit 4，fake whisper runtime 非零失败时返回既有 `processing_failed` / exit 5，并断言失败响应、processing log、capture checksum、derived artifact 污染和 retry success 边界。该 marker 不是公开 CLI 命令、字段、artifact、error code 或 exit code 契约，也不代表真实 native UI、真实 native capture、真实 release bundle 或所有开发机 runtime/model 环境 coverage。

同一脚本的 `capture-style concurrency/retry fixture` marker 用于 VS-MA-21 并发/重试证据：当另一个执行上下文持有同一 session lock 时，公开 `generate_transcript` 必须返回既有 `path_conflict` / exit 3，不登记 `normalized_audio` 或 `transcript_text`，不留下临时输出；释放 lock 后同一 session 重试必须成功生成 transcript，并保持原始 capture artifact checksum 不变。该 marker 同样不是公开契约，也不代表 release-scope 真实 native capture 并发覆盖。

`release-capture-processing-hardening-smoke.sh` 是发布候选路径使用的 VS-MA-21 provider hardening wrapper：它运行同一个 `capture-processing-smoke.sh`，保留完整 stdout/stderr log，再调用 `capture_processing_hardening_report.py --release-scope` 生成结构化 report。成功 report 声明 `release_gate=release-scope-provider-hardening` 和 `not_release_readiness=true`，并逐项记录 no-auto-download dependency preflight、default/fallback capture-style pipeline、path/lock/temp/checksum rollback、provider failure redaction、retry success、capture checksum preservation 和 pass marker 是否存在。该 wrapper 已注册到 `scripts/release-preflight.sh`，但排在 `product-validation-check.py release` 之后；当前发布范围 `PV-MA-*` 仍有 `partial` 时，release preflight 会先 fail closed，不会把 provider hardening wrapper 通过误写成 VS-MA-23 readiness。该 wrapper 不证明真实 ScreenCaptureKit 并发、native UI release-scope 并发、release distribution bundle 或 release readiness。

`release-native-ui-hardening-smoke.sh` 是发布候选路径使用的 VS-MA-21 native UI hardening wrapper：它先运行 `MA_NATIVE_APP_REAL_CAPTURE_SMOKE=1 ./platform/native-app/scripts/test-app-bundle.sh`，再运行 `MA_NATIVE_APP_VSMA21_HARDENING_SMOKE=1 ./platform/native-app/scripts/test-app-bundle.sh`，保留两段 app-bundle XCUITest 输出，再调用 `release_native_ui_hardening_report.py --release-scope` 生成结构化 report。`test-app-bundle.sh` 默认 `MA_NATIVE_APP_REUSE_XCTESTRUN=auto`，会在 native app source、UI tests、Xcode project、destination 和 Xcode 版本指纹未变时复用同一个 `.xctestrun` 和 `MeetingAssistantNative.app`，避免 release native UI hardening 复跑时因 Debug ad-hoc rebuild 触发新的 macOS TCC 授权项；输入变化时仍会 rebuild 并可能需要一次重新授权。成功 report 声明 `release_gate=release-scope-native-ui-hardening` 和 `not_release_readiness=true`，并确认 real capture app-bundle pass marker、VS-MA-21 hardening app-bundle pass marker、`path_conflict`、`Processing failed.` 与 `Processing complete.` marker 都存在。若 real capture 被 macOS TCC 权限阻断，report 会写入本次 DerivedData、app bundle、bundle id、signature、cdhash、designated requirement、xcodebuild log、xcresult 和 TCC remediation 字段，避免只靠 stdout 翻找授权目标或把旧 Debug ad-hoc `MeetingAssistantNative` 条目误认为当前 app bundle 已授权。report 还会记录 Apple adapter 支持 combined recording、不支持独立 system/microphone audio artifacts，并会尝试从 combined recording 导出 `mixed_audio`，但不会把这项 source capability 写作真实 release-scope 抽取通过。该 wrapper 已注册到 `scripts/release-preflight.sh`，排在 release-scope native capture gate 之后、provider hardening gate 之前；当前发布范围 `PV-MA-*` 仍有 `partial` 时，release preflight 会先 fail closed，不会把 native UI hardening wrapper 通过误写成 VS-MA-23 readiness。该 wrapper 不证明完整真实 capture -> transcript/export/delete 同链路、独立系统/麦克风音频产物、全目标机器 TCC/display、release bundle 或 release readiness。

`release-security-supply-chain-smoke.sh` 是发布候选路径使用的 VS-MA-22 security/supply-chain wrapper：它保留 `security-check`、`supply-chain-check current` 和 `release-provider-smoke` 的完整日志，再调用 `release_security_supply_chain_report.py --release-scope` 生成结构化 report。成功 report 声明 `release_gate=release-scope-security-supply-chain` 和 `not_release_readiness=true`，并逐项记录 production component security reports、supply-chain reports、runtime/model/audio `.local` 边界、model sha256/license/provenance sidecar、required whisper.cpp smoke 和 no-auto-download/no-auto-upload marker 是否存在。该 wrapper 已注册到 `scripts/release-preflight.sh`，但仍排在 `product-validation-check.py release` 之后；当前发布范围 `PV-MA-*` 仍有 `partial` 时，release preflight 会先 fail closed，不会把该 wrapper 通过误写成 VS-MA-23 readiness。该 wrapper 不证明签名/公证分发包、SLSA/release provenance attestation、所有机器 runtime/model sidecar、真实 ScreenCaptureKit 或 release readiness。

`release-sidecar-target-smoke.sh` 是 VS-MA-22 的逐目标机器 sidecar repeatability evidence 入口：它运行 processing-owned `release-provider-smoke.sh`，保留 provider log，再调用 `release_sidecar_target_smoke_report.py` 生成 `release_gate=release-sidecar-target-smoke` report。成功 report 绑定当前 commit、target id/os/architecture、runtime/model/audio `.local` digest、model license/provenance sidecar digest，以及 `check_dependencies`、`whisper.cpp` smoke 和 no-auto-download marker。该 report 只证明当前 target machine，可作为 release sidecar portability report 中某一个 `target_machines[].smoke_report` 的输入；它不声明 `target_scope=all-target-machines`，不能替代签名/公证 release bundle、SLSA provenance、Sigstore signing 或 VS-MA-23 readiness。

`release-sidecar-portability-report.sh` 是 VS-MA-22 的 all-target sidecar portability 输入生成器：它要求 `MA_RELEASE_SIDECAR_TARGET_SMOKE_REPORTS` 指向本次 release rehearsal 收集到的逐目标机器 report，要求 `MA_RELEASE_SIDECAR_EXPECTED_TARGETS` 声明完整 target id 列表，然后生成 `.harness/release-inputs/supply-chain/release-sidecar-report.json`。如果缺少 expected target、target report 未通过、report commit 不匹配、digest 不可校验、存在额外 target 或任一 expected target 未覆盖，生成器会写 `target_scope=incomplete-target-set` 并失败，避免把单机 evidence 误当 all-target release sidecar portability。

`native-capture-artifact-smoke.sh` 是 VS-MA-14/15 的显式 opt-in 跨组件 smoke：只有设置 `MA_NATIVE_CAPTURE_SMOKE=1` 时才调用真实 ScreenCaptureKit `platform/native-app/scripts/native-capture-smoke.sh`，随后用 `processing-cli` 的 workspace contract 读取同一 `session.json` 和四类原始 artifact，校验 `screen_video` checksum、音频 artifact 的缺失/降级原因或可用 `mixed_audio` checksum、managed relative path，并在无可用音频时断言 `generate_transcript` 以既有 `artifact_missing` fail closed 且不登记 `normalized_audio`、`transcript_text` 或 `speaker_labels`；如果本次 capture 已登记 `mixed_audio` available，则只记录原始 artifact 可用性，不把该 report 扩大为真实转写链路证明。该脚本默认最多尝试 2 次，底层 native smoke 可用 `MA_NATIVE_CAPTURE_SMOKE_TIMEOUT_SECONDS` 对真实 executable 运行阶段设置超时，失败时保留 summary 并调用 `native_capture_artifact_report.py --failure-report` 生成结构化诊断 report；该 report 汇总 `failure_stage`、start/stop response、validation errors、display wake guard、attempt count、TCC/display/runtime/timeout 诊断和 remediation hints，但保留 native smoke 原始失败退出码。通过时同一生成器会生成结构化 JSON evidence report，默认写入 `platform/e2e/build/native-capture-artifact-smoke/reports/`，也可用 `MA_NATIVE_CAPTURE_ARTIFACT_SMOKE_REPORT` 显式指定路径。默认 report 声明 `release_gate=partial-evidence-only`、`not_release_readiness=true`；成功 report 记录四类原始 artifact 状态、`screen_video` bytes/checksum 校验、音频降级原因或 `mixed_audio` checksum、processing no-audio fail-closed 或跳过原因，以及无派生产物污染。默认还会用 `MA_NATIVE_CAPTURE_ARTIFACT_SMOKE_DISPLAY_WAKE_SECONDS=120` 和 `MA_NATIVE_CAPTURE_ARTIFACT_SMOKE_DISPLAY_WAKE_SETTLE_SECONDS=3` 启动 `caffeinate -d -u` display wake guard，避免本机显示器休眠把真实 capture 误判为无 display。该脚本不属于默认 full-stack gate；通过也仍是 partial evidence，不证明所有 macOS/TCC 环境、独立系统/麦克风音频产物、生产默认真实 capture、native UI 触发 processing provider 或 release readiness。

`release-native-capture-artifact-smoke.sh` 是发布候选路径使用的 VS-MA-14/15 release-scope wrapper：它固定设置 `MA_NATIVE_CAPTURE_SMOKE=1` 和 `MA_NATIVE_CAPTURE_RELEASE_SCOPE=1` 后调用同一个 native capture artifact smoke，使 report 声明 `release_gate=release-scope-native-capture`。该 wrapper 已注册到 `scripts/release-preflight.sh`，但会排在 `product-validation-check.py release` 之后；因此当前发布范围 `PV-MA-*` 仍有 `partial` 时，release preflight 会先 fail closed，不会把 release wrapper 通过误写成 VS-MA-23 readiness。该 wrapper 通过后仍保持 `not_release_readiness=true`，不证明独立系统/麦克风音频真实产物、跨机器 TCC/display 可重复、完整 native-to-processing 成功 transcript 链、真实 Save Panel、release distribution bundle 或 release readiness。

`release-real-capture-same-chain-smoke.sh` 是发布候选路径使用的 VS-MA-21 非 UI real capture same-chain wrapper：它复用 release-scope native capture artifact smoke，默认请求 `MA_NATIVE_CAPTURE_SMOKE_SYSTEM_AUDIO=true`，要求真实 ScreenCaptureKit capture 产出 `mixed_audio available`，然后通过公开 `platform/e2e/ma-cli-local.sh` 串联 `generate_transcript -> generate_speaker_labels -> export_transcript -> delete_session`。默认 processing runtime 是 fake adapter；需要证明当前本机真实 runtime 功能时，显式设置 `MA_REAL_CAPTURE_SAME_CHAIN_TRANSCRIPTION_RUNTIME=whisper_cpp`，并提供 `MEETING_ASSISTANT_TRANSCRIPTION_RUNTIME`、`MEETING_ASSISTANT_TRANSCRIPTION_MODEL` 和 `MEETING_ASSISTANT_WHISPER_SMOKE_AUDIO`。该 opt-in 模式会把本地 fixture 传给 `native-capture-smoke.sh` 的 `MA_NATIVE_CAPTURE_SMOKE_AUDIO_PLAYBACK_PATH`，录制窗口内播放音频，再检查真实 transcript/export 中包含 `http`、`llm`、`clean architecture` 和 `eda` 等 mixed-language terms。成功 report 声明 `release_gate=release-scope-real-capture-same-chain`、`not_release_readiness=true`、`native_capture_to_processing_same_chain_proven=true` 和 `native_ui_same_chain_proven=false`，并记录 transcript、speaker fallback、export retention、delete 和原始 `mixed_audio` checksum preservation。该 wrapper 已注册到 `scripts/release-preflight.sh`，排在 release-scope native capture gate 之后、native UI hardening gate 之前；当前发布范围 `PV-MA-*` 仍有 `partial` 时，release preflight 会先 fail closed，不会把该 wrapper 通过误写成 VS-MA-23 readiness。它证明真实录制产物的数据链路进入 processing/export/delete，不证明 app-bundle/native UI 点击链路、XCUITest Automation Mode、真实用户 Save Panel、release bundle 或 release readiness。

`MA_NATIVE_APP_REAL_CAPTURE_REAL_RUNTIME_SAME_CHAIN_SMOKE=1 ./platform/native-app/scripts/test-app-bundle.sh` 是 VS-MA-23 的本机功能 app-bundle smoke，不注册到默认 full-stack 或 release-preflight。它在 launched `.app` 真实录制期间通过 `/usr/bin/afplay` 播放 `MEETING_ASSISTANT_WHISPER_SMOKE_AUDIO`，要求 ScreenCaptureKit 产出的真实 `mixed_audio` 进入 provider-owned `platform/e2e/ma-cli-local.sh`，并用用户显式配置的 `MEETING_ASSISTANT_TRANSCRIPTION_RUNTIME` / `MEETING_ASSISTANT_TRANSCRIPTION_MODEL` 以 `whisper_cpp` 生成真实 transcript，再完成 transcript review、copy/export 和 delete confirmation。通过只证明当前本机直接运行功能链路，不证明签名、公证、App Store、跨机器 TCC/UI Automation、真实用户 Save Panel、release distribution bundle 或 release readiness。

`release-local-direct-target-smoke.sh` 是 VS-MA-23 的逐目标机器 local-direct repeatability evidence 入口：它运行 `local-direct-same-chain-smoke.sh`，保留 same-chain log，再调用 `release_local_direct_target_smoke_report.py` 生成 `release_gate=release-local-direct-target-smoke` report。成功 report 绑定当前 commit、target id/os/architecture、installed app identity、same-chain report digest、三段 stage 通过状态、默认 `open` launch mode、expected transcript terms、system pasteboard、`NSSavePanel` export 和 delete markers。该 report 只证明当前 target machine，不声明 `target_scope=all-target-machines`，不打开 System Settings、不修改 TCC、不要求 Developer ID/公证，也不证明 `release-preflight` 或商业分发 readiness。

local-direct same-chain 使用音频 fixture 时，recording stage 会先满足 `MA_NATIVE_LOCAL_APP_RECORDING_SMOKE_DURATION_SECONDS`，再等待 fixture 在 `MA_NATIVE_LOCAL_APP_RECORDING_SMOKE_AUDIO_GRACE_SECONDS` 内播放完成，避免 transcript expected terms 被提前 stop 截断。processing stage 优先使用 UI completion marker；如果点击 Start Processing 后 macOS AX/window observation 丢失 completion marker，只有结构化 `normalized_audio`、`transcript_text`、`speaker_labels`、expected terms 和 speaker-label fallback 全部通过时，才允许 `artifact_completion_fallback=true` 的 report 通过，并保留 `ui_completion_observation_error`。

`release-local-direct-repeatability-report.sh` 是 VS-MA-23 的 all-target local-direct repeatability 输入生成器：它要求 `MA_RELEASE_LOCAL_DIRECT_TARGET_SMOKE_REPORTS` 指向本次 rehearsal 收集到的逐目标机器 `release-local-direct-target-smoke` report，并要求 `MA_RELEASE_LOCAL_DIRECT_EXPECTED_TARGETS` 声明完整 target id 列表，然后生成 `.harness/release-inputs/local-direct/release-local-direct-repeatability-report.json`。如果缺 expected target、target report 未通过、report commit 不匹配、存在额外 target 或任一 expected target 未覆盖，生成器会写 `target_scope=incomplete-target-set` 并失败，避免把单机 local-direct evidence 误当全目标 repeatability 或 PV/release readiness。

`local-direct-functional-preflight.sh` 是 VS-MA-23 的本机功能 preflight，不是发布候选门禁。它运行 local-direct target smoke，再用当前单台 target 作为显式 expected target 生成 repeatability report，最后由 `local_direct_functional_preflight_report.py` 写出 `release_gate=local-direct-functional-preflight`、`target_scope=local-machine-only` report。通过表示当前已授权本机 installed local-direct app 的 recording -> processing -> transcript actions 链路可复跑；report 仍声明 `not_release_readiness=true`，不证明跨机器 TCC/display/UI Automation、`PV-MA-* covered`、`release-preflight`、Developer ID、公证、App Store 或商业化分发 readiness。

`./platform/native-app/scripts/install-local-app.sh` 是 VS-MA-23 的普通本机 local-direct app install 入口，默认把 Release app 复制到稳定用户路径 `~/Applications/MeetingAssistantNativeLocal.app`。它先接受 source app 的 `CFBundleIdentifier=local.meeting-assistant.native`、`CFBundleName=MeetingAssistantNative` 和本地 codesign 验证，再把安装副本改成本机专用身份：`CFBundleIdentifier=local.meeting-assistant.native.localdirect`、`CFBundleName=MeetingAssistantNativeLocal`、`CFBundleDisplayName=Meeting Assistant Native Local`，随后用 local ad-hoc signing 重新签名并 verify，避免 TCC 授权目标和 Debug/XCUITest/旧 worktree 的同名 app 混淆。已存在安装目标必须是旧 source identity 或新的 local-direct identity，避免覆盖无关应用。安装成功后写出 `platform/native-app/build/local-app-install/local-app-install-report.json`，记录 source app identity、installed app identity、codesign `CDHash`、`local_tcc_identity_strategy`、不打开系统设置/不修改 TCC/不要求 Developer ID 的边界字段，以及 direct recording diagnostic 命令。该脚本不打开 System Settings、不修改 TCC、不要求 Developer ID/公证/Stapler/Sigstore/App Store 分发。安装后可用 `MA_NATIVE_LOCAL_APP_PATH="$HOME/Applications/MeetingAssistantNativeLocal.app" ./platform/native-app/scripts/run-local-app.sh --no-build` 或 `./platform/native-app/scripts/local-direct-recording-smoke.sh --no-build --app "$HOME/Applications/MeetingAssistantNativeLocal.app"` 针对稳定安装路径复跑本机功能。

`./platform/native-app/scripts/local-app-permission-diagnostics.sh` 是本机权限诊断入口，会读取 install report 和最近一次 recording smoke report，写出 `platform/native-app/build/local-app-permission-diagnostics/local-app-permission-diagnostics-report.json`，其中包含 recommended TCC target path/`CFBundleDisplayName`/CDHash、install report 的 `local_tcc_identity_strategy`、是否为同一 app identity、Screen Recording denied 状态、授权后推荐复跑命令和 direct launch diagnostic 命令。该脚本只读，不打开 System Settings、不修改 TCC、不要求 Developer ID/公证；它用于减少本机授权目标误判和区分 LaunchServices/TCC attribution，不证明授权已完成。

local-direct 默认以 `MA_NATIVE_CAPTURE_SMOKE_SYSTEM_AUDIO=true`、`MA_NATIVE_CAPTURE_SMOKE_MICROPHONE_AUDIO=false` 跑当前 same-chain 功能路径；需要验证麦克风路径时显式覆盖 flags。`local-direct-recording-smoke` 失败 report 会保留 recording request flags、app identity、permission failure details 和 stale TCC identity hint，避免把同名但不同 path/CDHash 的 `MeetingAssistantNative` 授权项误认为当前 Release app 已授权。

`native-transcript-bridge-smoke.sh` 覆盖 integration-only 的 processing-to-native transcript bridge：同样通过公开 `processing-cli` 生成临时 workspace/session artifacts，保留 `session.json`、`transcript.json` 和 `speaker_labels.json`，再用临时 SwiftPM harness 调用 `TranscriptReviewWorkspaceLoader` 与 `TranscriptReviewViewModel` 只读消费同一 workspace，断言 transcript text、segment count 和 transcript-only degradation 可投射到 native read model。该 Swift harness 还断言 `MeetingAssistantNativeApp.swift` 的 app root 挂载 `DesignedNativeShellView`，而不是直接挂载 primitive debug UI，并验证 designed shell 的 section、`ma.shell.*` locator 和核心子 view wiring。它不注册新 product command、不调用真实 capture、不调用真实 external runtime，也不替代 app-bundle XCUITest locator 覆盖。

`full-stack-smoke.sh` 是 manifest 注册入口，顺序运行 import processing local smoke、native_recording-style provider smoke 和 native bridge + designed shell smoke；当显式设置 `MA_NATIVE_CAPTURE_SMOKE=1` 时，会在 provider smoke 和 native bridge 之间追加真实 native capture artifact smoke；当显式设置 `MA_NATIVE_APP_MVP_FULL_STACK_SMOKE=1` 时，会追加 native app-bundle MVP full-stack smoke，调用 `platform/native-app/scripts/test-app-bundle.sh` 的 `MA_NATIVE_APP_MVP_FULL_STACK_SMOKE=1` 分支，证明 designed shell 可在同一 workspace/session 中触发受控 native recording、provider-owned CLI processing、transcript review、copy/export 和 delete confirmation。默认不设置这些 env 时只输出 optional stage skipped，不尝试 ScreenCaptureKit、macOS TCC 权限或 Xcode UI automation。最终 pass marker 只输出 VS-MA-20 provider/e2e attribution、VS-MA-21 provider/e2e hardening 和 VS-MA-21/PV blocker reminder；这些 marker 不得写作 VS-MA-23 release readiness。VS-MA-20 app-bundle stage 仍是 opt-in partial evidence，不证明真实 ScreenCaptureKit 输出、真实用户 Save Panel、release distribution bundle 或 release readiness；VS-MA-21 hardening summary 只说明 provider/e2e 侧本地命令链、capture-style provider artifact/failure-redaction/retry/checksum 链和 native read bridge / designed shell app-root smoke 通过。发布候选是否可进入人工审查仍以 `./scripts/product-validation-check.py release`、`./scripts/release-preflight.sh` 和验证矩阵中的 `PV-MA-*` 状态为准。`platform/processing-cli/scripts/test.sh` 仍直接调用 processing-owned smoke，避免 processing 组件测试反向依赖 native/Xcode 工具链。

`prepare-smoke-image.sh` 只复用本机已缓存的允许基础镜像并打成本地 smoke tag；它不会在 E2E 执行阶段从外部 registry 拉取镜像。脚本会在有界窗口内反复扫描 target 和允许的 cached base images，以吸收 Docker Desktop image-store 短暂不可用；没有可用缓存时，标准 E2E 应明确失败并提示预加载镜像。
